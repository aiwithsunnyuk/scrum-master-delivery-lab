# Milestone 04 — Agile Metrics & Delivery Transparency

## Objective

Demonstrate how a Scrum Master uses empirical data to improve transparency and enable better conversations without turning metrics into individual performance targets.

## Metrics model

**Outcome first → Flow → Predictability → Quality → Improvement**

### Core measures

- Sprint Goal achievement
- Forecast vs completed work
- Capacity
- Velocity trend
- Cycle time
- Spillover
- Defect trend
- Impediment aging

## Evidence

- `data/sprint-metrics.csv`

## Exit criteria

The metrics view should help answer:

1. Did we achieve the Sprint Goal?
2. What did we forecast and complete?
3. What changed during the Sprint?
4. How is flow behaving?
5. What quality signals are visible?
6. What should the team inspect and improve?

## Guardrails

Metrics are used to support inspection and adaptation.

They are **not** used to:

- Rank Developers.
- Compare individuals.
- Set a mandatory velocity target.
- Treat story points as hours.
- Reward teams for inflating estimates.
