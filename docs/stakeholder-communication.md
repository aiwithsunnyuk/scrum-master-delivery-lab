# Stakeholder Communication

## Principle

Transparency should reduce surprise, not create noise.

## Example update

### Situation
Sprint 05 remains focused on request-status visibility.

### Progress
Core status journey is progressing toward the Sprint Goal.

### Risk
An additional feature request has emerged from an upcoming customer demonstration.

### Decision path
The Product Owner will evaluate the request against current priorities and the Product Goal.

### Scrum Master action
Facilitate alignment and ensure the team is protected from conflicting priority channels.

## Communication rules

- State facts before interpretation.
- Make impact explicit.
- Name the decision owner.
- Explain options and trade-offs.
- Avoid promising dates without team evidence.
- Close the loop after decisions.
